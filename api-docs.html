soc_reader_client

Client Python de lecture seule vers OpenSearch. Interroge événements et alertes du SIEM, renvoie des objets Python prêts à stocker.

lecture seule auth + TLS opensearch-py

Structure du module

Le paquet soc_reader_client/ regroupe quatre fichiers, chacun avec une responsabilité unique. C'est ce dossier — et lui seul — qu'on copie chez le consommateur (backend, MCP…).

soc_reader_client/
├── __init__.py   # point d'entrée : expose SOCReader, OpenSearchConfig
├── config.py     # config via variables d'environnement (aucun secret en dur)
├── client.py     # classe SOCReader : connexion TLS + méthodes de requête
└── models.py     # LogEvent / Alert : mapping OpenSearch → objets + to_dict()
FichierRôle
__init__.pyrend le paquet importable : from soc_reader_client import SOCReader
config.pylit host, port, identifiants, TLS depuis l'environnement ; définit les noms d'index
client.pyouvre la connexion et fournit toutes les méthodes : recherche, agrégation, pagination
models.pyconvertit les documents bruts en objets Python ; point d'alignement avec le schéma PostgreSQL
Un seul dossier à déployer. Le paquet est autonome : sa seule dépendance externe est opensearch-py. Rien d'autre du dépôt n'est nécessaire au consommateur.

Copier le dossier chez le consommateur

Pour que le backend puisse faire from soc_reader_client import SOCReader, le dossier doit se trouver là où tourne son code. Marche à suivre :

# 1. copier le paquet dans le dépôt du backend, sur la VM plateforme
scp -r soc_reader_client/ soc-platform@10.10.40.20:~/soc-platform/backend/

# 2. installer la dépendance dans l'environnement du backend
pip install opensearch-py

# 3. configurer la connexion (OpenSearch est sur SOC01, pas en local)
export SOC_OS_HOST=10.10.40.10
export SOC_OS_PORT=9201
export SOC_OS_PASSWORD='...'

# 4. le backend importe et utilise
python3 -c "from soc_reader_client import SOCReader; print(SOCReader().ping())"

Importer & instancier

Le module s'importe comme une librairie. La configuration est lue depuis l'environnement à la construction — aucun identifiant en dur.

from soc_reader_client import SOCReader

reader = SOCReader()          # config lue dans l'environnement
reader.ping()                  # True si le cluster répond
Prérequis. Exporter au minimum SOC_OS_PASSWORD. Sur la VM plateforme, définir aussi SOC_OS_HOST=10.10.40.10 (OpenSearch tourne sur SOC01).

Connexion

ping() → bool

Retourne True si le cluster répond. Interroge un index autorisé (pas la racine, interdite au compte restreint).

reader.ping()
True

Recherche d'événements

search_events(start, end, host, index, size, extra_filters) → list[dict]

Événements de logs (ECS), triés du plus récent au plus ancien. Retourne les documents bruts (_source).

ParamTypeRôle
start, endstr | Nonebornes temporelles — "now-24h" ou ISO 8601
hoststr | Nonevaleur exacte de host.name
indexstrdéfaut : logs Windows + Linux
sizeintnombre max de résultats (défaut 100)
extra_filterslist | Noneclauses DSL supplémentaires
reader.search_events(start="now-24h", host="PC-WIN01", size=50)
[{'@timestamp': '2026-08-09T02:10:44Z', 'host': {...}, 'event': {...}}, ...]
search_events_typed(...) → list[LogEvent]

Identique à search_events, mais renvoie des objets LogEvent. À privilégier côté backend.

for ev in reader.search_events_typed(start="now-1h"):
    print(ev.host, ev.event_action, ev.destination_ip)
OPNsense.internal pass 199.232.210.172

Retour — liste d'objets LogEvent. La ligne affiche l'hôte source (OPNsense.internal), l'action de l'événement (pass = paquet autorisé) et l'IP de destination. Chaque LogEvent expose aussi source_ip, process_name, etc. (voir le modèle LogEvent).

Recherche d'alertes

search_alerts(start, end, agent_name, rule_id, min_level, index, size) → list[dict]

Alertes Wazuh. Les champs Wazuh sont sous wazuh.* (le vrai agent, pas le collecteur).

ParamTypeRôle
agent_namestr | Nonefiltre sur wazuh.agent.name
rule_idstr | Nonefiltre sur wazuh.rule.id
min_levelint | Nonewazuh.rule.level ≥ min_level
reader.search_alerts(start="now-24h", agent_name="pc-lnx01", min_level=7)
[{'@timestamp': '...', 'wazuh': {'rule': {'level': 10, ...}}}, ...]
search_alerts_typed(...) → list[Alert]

Identique à search_alerts, mais renvoie des objets Alert.

for al in reader.search_alerts_typed(start="now-1h", size=5):
    print(al.agent_name, al.rule_level, al.rule_description)
pc-lnx01 3 ClamAV database update

Retour — liste d'objets Alert. La ligne affiche l'agent qui a émis l'alerte (pc-lnx01), le niveau de la règle (3) et sa description. À noter : agent_name est le vrai agent (wazuh.agent.name), pas le collecteur Filebeat.

Agrégations

top_hosts(start, end, index, field, n) → list[tuple[str, int]]

Top N des hôtes par nombre d'événements sur la période.

reader.top_hosts(start="now-24h", n=5)
[('pc-ln01', 43745), ('srv-web01', 34579), ('DC01.corp.lab.local', 15064)]

Retour — liste de tuples (nom_hôte, nombre_d_événements), du plus actif au moins actif. Ici : l'hôte pc-ln01 a généré 43 745 événements sur la période.

count_by_severity(start, end, index, field, n) → list[tuple]

Répartition des alertes par niveau de sévérité.

reader.count_by_severity(start="now-24h")
[(3, 1284), (5, 210), (7, 44), (10, 3)]

Retour — liste de tuples (niveau_de_sévérité, nombre_d_alertes). Ici : 1284 alertes de niveau 3, 210 de niveau 5, 44 de niveau 7, 3 de niveau 10. Le niveau correspond à wazuh.rule.level (échelle Wazuh 0–15, plus le nombre est élevé, plus c'est critique).

Findings des détecteurs

search_findings(start, end, detector_name, index, size) → list[dict]

Findings produits par les détecteurs Security Analytics (règles Sigma). Champ temporel : timestamp (epoch ms). search_findings_typed(...) renvoie des objets Finding.

ParamTypeRôle
detector_namestr | Nonefiltre exact sur monitor_name
for f in reader.search_findings_typed(detector_name="Detector-Windows"):
    print(f.severity, f.rule_names, f.attack_techniques)
low ['Potential Data Exfiltration - ...'] ['attack.exfiltration', 'attack.t1041']

Retour — search_findings renvoie une liste de dictionnaires bruts ; search_findings_typed une liste d'objets Finding. Chaque finding expose notamment severity (sévérité de la règle Sigma), rule_names (règles qui ont matché) et attack_techniques (techniques MITRE ATT&CK).

list_detectors(index, n) → list[tuple[str, int]]

Liste les détecteurs présents dans les findings, avec leur nombre. Utile pour connaître les detector_name disponibles (des détecteurs supprimés peuvent laisser des orphelins).

reader.list_detectors()
[('Detector-Windows', 43)]

Retour — liste de tuples (nom_du_détecteur, nombre_de_findings). Ici : le détecteur Detector-Windows a produit 43 findings.

Alertes de détecteur

search_detector_alerts(start, end, detector_name, state, index, size) → list[dict]

Alertes déclenchées par les triggers des détecteurs. Distinctes des findings (elles les référencent via finding_ids et ont un state). Champ temporel : start_time (epoch ms). Index courants par défaut ; passer index=INDEX_DETECTOR_ALERTS_ALL pour l'historique. search_detector_alerts_typed(...) renvoie des objets DetectorAlert.

ParamTypeRôle
detector_namestr | Nonefiltre exact sur le détecteur
statestr | NoneACTIVE, ACKNOWLEDGED, COMPLETED, ERROR
for a in reader.search_detector_alerts_typed(detector_name="Detector-Windows"):
    print(a.start_time, a.trigger_name, a.severity_label, a.state)
2026-08-03T23:54:20 Trigger 1 critical ACTIVE

Retour — liste d'objets DetectorAlert. Chaque ligne affiche l'heure de départ, le trigger déclencheur (Trigger 1), la sévérité lisible (critical) et l'état de l'alerte (ACTIVE).

Intégration backend (M1)

Le backend importe la brique, lit, puis insère dans PostgreSQL. Il n'y a pas d'API réseau entre les deux. Chaque to_dict() fournit les valeurs lisibles + donnees_brutes (doc complet) + severite déjà convertie vers l'enum M1.

from soc_reader_client import SOCReader

reader = SOCReader()
for alerte in reader.search_alerts_typed(start="now-5m"):
    d = alerte.to_dict()
    # le backend résout les UUID et insère :
    agent_id = resoudre_agent(d["agent_name"], d["agent_ip"])
    regle_id = resoudre_regle(d["rule_id"])
    AlerteCreate(regle_id=regle_id, agent_id=agent_id,
                 severite=d["severite"], donnees_brutes=d["donnees_brutes"])

Conversion de sévérité — la brique traduit chaque échelle vers l'enum M1 (faible / moyenne / haute / critique), exposée sous la clé severite :

SourceOrigine→ enum M1
Alert (Wazuh)niveau 0–4 / 5–7 / 8–11 / 12–15faible / moyenne / haute / critique
Finding (Sigma)low / medium / high / criticalfaible / moyenne / haute / critique
DetectorAlert"4","5" / "3" / "2" / "1"faible / moyenne / haute / critique
Résolution des UUID côté backend. La table alertes référence agents et regles par UUID (FK obligatoires). La brique fournit les valeurs lisibles ; M1 les résout. Détail et points ouverts dans INTEGRATION_M1.md.
